A full-duplex voice agent must keep answering small, closed questions — has the user finished? which filler fits? which step of the flow is this? DuplexJev reads every such question as one constrained token from a frozen speech LLM. No ASR decoding, no text decoding, and many questions — over one call or across calls — share a single forward pass.

How it works

Typed single-token readout

Each question lists its options under letters in a random order. The answer is the LLM's next-token distribution restricted to those letters — always a valid option, with a confidence score for free.

Prefix sharing

The shared prefix (dialogue context and audio) is encoded once; all questions are packed into one row under a block-diagonal mask. Memory grows with the questions, not with copies of the context.

Paralinguistics through fusion

Variant A lets the final encoder layer attend to layers 14 and 9, where speaker and prosody cues survive. The fusion starts at zero, so A begins identical to the last-layer variant B.

Swap the parts

Encoder and LLM stay frozen; only a 40 M-parameter projector (plus 3 M for fusion) is trained. Any open ASR encoder and any LLM that accepts input embeddings will do.

Ten decisions: 92 ms instead of two seconds

Same GPU (1× H200), same frozen Qwen3-32B, same vLLM engine. The cascade transcribes, then generates the ten answers as JSON; the readout answers them as single tokens.

Long contexts stop multiplying

Wall time for N questions over one utterance (plain PyTorch, eager attention; ratios are what matter). Shared and one-by-one answers agree on 195/200 and 198/200 items for the two variants and 40/40 with 0.5–5k-token contexts; remaining differences are near-ties at bf16 precision.

One clock for every call

Because a decision is a single step, a server can gather the latest audio of every active call on a fixed tick and answer all of them in one batch — something a cascade cannot do, since each transcription needs its own sequence of decode steps. Understanding and paralinguistics

With a well-aligned speech path, reading the answer as one constrained token costs almost nothing against reading the transcript: 89 vs 91 on qa100 (Ultravox v0.6 Whisper path, Qwen3-32B). Results for our released speech paths — qa100, the ZJU gender benchmark and the ZJU main-language benchmark with real speech — will appear here with the final checkpoints. pending

Limitations

  • Turn-taking from audio is not solved yet: current speech paths stay near the prior on Easy-Turn, while the same readout reaches 84.9% from the transcript.
  • qa100 is synthetic speech; real-speech understanding is measured on the ZJU main-language benchmark.
  • Confidence gates abstention but does not reveal a missing skill: a path that cannot hear gender is still confident.
  • Gender labels are corpus-provided and binary; the classifier is a probe of information flow, not a tool for identifying people.
