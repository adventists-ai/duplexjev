# 一个 rank 16 的 LoRA，让语音判断大模型的话轮能力追上专用检测器

*Adventists.ai 研究笔记，2026-10-05。[English](2026-10-turn-taking-lora.md)*

*DuplexJev 把语音智能体需要的判断（话轮、情绪、意图……）读成"直接听音频"的大模型输出的一个 token。*
**再加一个用公开话轮数据训练的 rank 16 LoRA，话轮能力就追上了专用检测器：** DuplexJev-32B-Turn 在 Easy-Turn 上 95.3
（专用检测器 96.4），CoDeTT 零样本 69.2 / 70.0（Qwen3-Omni 70.4 / 70.9；专用话轮模型 37.9–65.4），其他能力都没变差。

和专用检测器不同，它仍是通用判断引擎：同一次前向还能回答其他任意闭集问题（意图、情绪、性别、是否打断……），
不需要解码，单张 H200 上 10 个判断约 0.24 秒。

## 起点

DuplexJev 把语音判断读成大模型的单 token 分布（编码器 → 训练过的连接器 → 大模型）。已发布的 DuplexJev-32B / 4B
主要为内容、性别、情绪训练，话轮只用过 Easy-Turn 训练集。在 CoDeTT 上零样本测，最主要的问题是**几乎总是"有反应"**：
助手说话时，听到附和和噪声也选"停下来听"（继续说只有 14–28%）；空闲时，用户没说完也接话。

## 做了什么

1. **数据：用公开语料改写出 11 万道话轮题**（除截断和噪声混合外，没有从头合成）：

   | 来源 | 条数 | 教什么 |
   |---|---:|---|
   | Easy-Turn 训练集（合成 + 真实部分） | 4.4 万 | 中文：说完 / 没说完 / 附和 / 等一下 |
   | SmoothConv（中文多人，逐段话轮标注） | 3 万 | 真实对话，带 1–5 轮文字历史 |
   | otoSpeech 双声道 + DualTurn 帧标签 | 1.25 万 | 英文：说完、停顿、附和、插话 |
   | DuplexGen Spoken | 1.4 万 | 英文人机对话，带历史；截断制造"没说完" |
   | MUSAN 噪声；远场、压低的背景人声 | 0.9 万 | 两种状态下都应忽略的声音 |

   60% 的题给出**系统状态**再问动作（说话中 → 继续说 / 停下来听；空闲 → 接话 / 继续等），40% 问用户的话轮状态。
   措辞与所有评测脚本都不同。
2. **模型：连接器和大模型上的 rank 16 LoRA 一起训**（q/k/v/o，占参数 0.6%），混合原有的内容蒸馏和副语言数据。
   试点中只训连接器，CoDeTT 也会涨，但 Easy-Turn 掉 9 分、VoiceBench 掉 4 分——一个小模块要同时承担对齐和话轮。
   LoRA 给了大模型空间去用好它已经听到的东西。
3. **一个关键细节**：内容蒸馏的老师（读转写的大模型）必须**关掉 LoRA** 再算。否则 LoRA 同时改老师和学生，
   KL 损失趋近 0，内容理解被训坏。
4. 发布时把 LoRA 合并进权重：大小、vLLM 插件、提示词都不变。

配方：批 16，学习率 1e-4，8000 步；4B 单张 H200 约 85 分钟，32B 四张 H200 约 2 小时。

数据权重、rank、步数的影响都在误差范围内（qa100 ±4，Easy-Turn ±1.5），配方不敏感。

## 仍然薄弱的地方

- **长话轮中间的停顿**：约一半被当成说完（TurnBench-dev 停顿类 54–57%）。
- **空闲时保持沉默**（用户没说完、取消、在和别人说话）：32B-Turn 的 CoDeTT"不接话"中文 37%、英文 46%。
- CoDeTT 口径差异：我们只给当前这句的音频；官方口径还会播放之前的用户语音。Gemini-3-Pro（约 81）仍明显领先。

## 局限

每个配置只跑一次。Easy-Turn 对我们的模型是域内评测（对 Easy-Turn 检测器本身也是）。TurnBench 数字用的是我们自建的片段协议。
其他系统的延迟取自各自论文和硬件。
