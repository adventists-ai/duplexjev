# 整段音频都听进去：6.5 与 6.25 的错位和 DuplexJev-32B-Para v1.5

*2026-11-03 · [English](2026-11-full-length.md) · 模型：[DuplexJev-32B-Para v1.5](https://huggingface.co/adventists-ai/DuplexJev-32B-Para)*

## 问题

DuplexJev 用 Qwen3-ASR-0.6B 编码器加连接器把语音送进大模型，连接器把两帧编码器输出叠成一个音频 token。我们的处理代码（训练用的
Ultravox 改版、`duplexjev` 包和 vLLM 插件）一直按 `ceil(mel 帧数 / 16)` 计算音频 token 数，也就是每秒 6.25 个，这是“编码器统一
8 倍下采样”时的数。

但 Qwen3-ASR 并不是统一 8 倍：它按 1 秒（100 个 mel 帧）一个窗口编码，每个窗口出 **13** 帧，所以连接器每秒产生 **6.5** 个音频
token。只留 6.25 个位置，每个 30 秒音频块末尾约 4%（每 12 秒约 0.5 秒，长音频更多）根本没有进到大模型。对多数判断影响不大，
但一句话的结尾恰恰是话轮判断、句末重音、结尾笑声所在的地方。

## 修正

- 处理代码改为按编码器自己的输出长度（`_get_feat_extract_output_lengths`）计算 token 数，训练和推理都改。
- v1.5 从 v1.4 出发按真实长度重训：两段（2,000 + 1,500 步，每段训连接器 + 新的 rank-16 LoRA，已合并），回放 v1.4 的完整配比，
  另加本族语指令、前后补静音的转写题（FLEURS dev 和 v1.4 的弱语种数据；FLEURS test 从未使用），并小幅回放全部情绪数据。
  训练日志里的长度自检从 0.96 变为 1.00。
- 旧模型不重训、直接改成全长没有用（内容持平、话轮略差）：连接器已经适应了截短的输入，所以必须重训。
- 兼容：v1.5 在 `config.json` 里写了 `"audio_full_length": true`。`duplexjev-vllm>=0.4` 和 `duplexjev>=0.7` 会读这个开关；
  旧模型仍按旧算法，行为完全不变（已验证：v1.4 用新插件跑 vLLM 验收，数字一致）。`DJ_FULL_LEN=1/0` 可强制覆盖。

## 结果（v1.4 → v1.5）

| | v1.4 | v1.5 |
|---|---:|---:|
| qa100 / ZJU-ML（vLLM） | 97 / 90 | **98 / 91** |
| 性别 / 情绪（vLLM） | 92.1 / 89.2 | **92.6 / 90.0** |
| Easy-Turn（vLLM） | 94.1 | **95.4** |

| eot-bench 英文，300 / 600 ms 误打断（快速模式，带助手上一句） | 20.4 / 8.9% | **17.7 / 7.0%** |
| eot-bench 中文 | 42.3 / 13.8% | **41.0 / 13.3%** |
| StressTest | 81.7 | **85.3** |

两列同一套评测。Smart Turn 训练集和 Easy-Turn 训练部分在我们的训练数据里（同分布）；eot-bench 的音频不在。

## 如果你用了我们的处理代码

凡是产生或使用 Qwen3-ASR 音频表示的地方都用了同一条计数规则。如果你在自己的训练或推理代码里用了我们的处理代码，请升级到
`duplexjev>=0.7` / `duplexjev-vllm>=0.4`，或者按上面的方法用编码器输出长度计算 token 数。
